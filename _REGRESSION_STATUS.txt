Native multi-artifact existing-army control
------------------------------------------

  #62..#65 and equips exactly three artifacts on each (12 artifacts total).
- Native allocation rule is recovered exactly: process DTm items_ids left-to-right;

  to Другой берег3.sav. Army #62 has exactly one native-load-only difference at

  QuestSync deliberately preserves the source model byte for a same-role unit
  instead of copying nondeterministic/opaque state from an independent load.

Derived formulas now implemented
================================

Upkeep / payment:
- Exact CalculateUpkeep formula from the editor.
- Round((Cost / CostGoldDiv / CostRecruitDiv) * K) using .NET banker's rounding.
- K = 0.25 / 0.50 / 0.75 / 1.00 for Cost <=50 / <=100 / <=150 / >150.
- CostRecruitDiv defaults to 2 when absent/invalid; CostGoldDiv <= 0 becomes 2.
- Level does not change upkeep. Legacy empirical payment profiles are no longer
  used.

Tactical strength / tactical cost:
- CalculateTacticalStrength and CalculateTacticCost were reconstructed from the
  IL of Editor1.3.10.1.exe and implemented in army_runtime.py.
- Formula covers attack-class selection, exponential defence power, protection,
  vampirism, initiative, magic direction and Bonus branches.
- Native game-runtime compatibility overrides the editor's two God bonuses:
  GodStrike +20 and GodAnger +10, as demonstrated by the supplied native SAVs.
- Production strict mode still prefers exact native profiles for observed
  Unit+Level and modified combinations, because a few game-runtime details do
  not exactly equal editor calculations. Unknown combinations fail safely
  instead of silently writing an unverified strength.

Format/runtime hardening
========================

- Runtime army slot: 0x3827 bytes; unit record: 0x1DB bytes; maximum 12 units.
- Same-count structural edits, multiple insert/delete operations and exact
  survivor reorders are supported.
- Middle insertion/reorder preserves +0x000..+0x7FF destination-slot header and
  moves +0x800..end with the mapped army.
- MapLDV V.4 Army-ID references are centralized: cell marker, building owner
  +292 and all 16 known EventData offsets.
- Strict post-build verifier checks slot size, unit count/composition, aggregate
  strength, HP sum, formation and rebuilt unit-area invariants.
- Empty-map cell-table fallback can locate the table from runtime army current
  coordinates and cell markers; markerless/inactive 100x100 and 200x200 native
  V.4 layouts are also supported by byte-certified geometry profiles.
- SAV text/dynamic-tail location no longer requires the scenario-title string
  to match the target DTm; it has a structural/text-table fallback.
- New unit runtime marker +0x1A6 is 1 as confirmed by the native all-unit corpus.

Conservative limits
===================

- DTm army records do not contain a stable GUID. A same-position delete+create
  that leaves no exact structural anchor is observationally indistinguishable
  from an in-place edit. The mapper intentionally chooses the conservative edit
  interpretation in that ambiguous case.
- For unchanged standard-game data, unseen Unit+Level or unseen modified spell/artifact combinations that require
  synthesis are rejected by production strict mode unless a usable native runtime template exists.
- If the live Rus_Units/Rus_Artefacts/Rus_Spells definition itself differs from the tested profile, the GUI warns that native testing was not performed and production intentionally permits the reconstructed formula fallback for that affected combination, as requested for mod compatibility.
- Opaque AI/slot header state is preserved from the destination SAV slot rather
  than guessed.
